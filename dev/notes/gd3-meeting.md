# 디자인팀 3차 회의록: 상점·보상 메뉴 나누기 (+ 진행 중 추가 요청)

팀(혼자서 네 역할을 맡음): 게임 UI/UX 디자이너 · UX 라이터 · 프론트엔드 · QA(접근성·줄바꿈)
고친 파일: `src/index.html` 하나뿐. 차이는 `gd3.diff`(base.html 대비, 770줄). 규칙 사본 `firestore.rules`는 **안 고침**.
다시 적용하는 스크립트: `tools/patch.py`(메뉴·탭·머리줄) → `tools/patch2.py`(상점 분류·돌/판 공개) → `tools/patch3.py`(칩·선/후·묘수 해설·베팅 강조·동전).
건드리지 않은 것: ecoWrite·ecoClaim·ecoClaimAll·attStamp·nickCommit, attLine/attShow/attStamp 안쪽과 .atrow/.atc/.attd CSS(코디네이터 지시), 대국 규칙·판정, RANK_MAINT=true, BOT_RESET 등 본선 신규분.

## 2. 안 비교와 결정

### 2-1. 메뉴 구조(하단 탭)
| 안 | 내용 | 점수 | 이유 |
|---|---|---|---|
| A | 6칸: 대국·랭크·친구·전적·**보상·상점** + 규칙은 머리줄 **?** 버튼 | **96** | 360px에서 칸당 57px, 2글자+22px 그림이라 여유 있음(큰 글씨 모드 포함 잘림 0). 받을 것은 보상 탭 숫자 배지. 상점이 앞으로 늘어도 한 탭 전체를 씀 |
| B | 7칸(규칙 탭 유지) | 78 | 360px에서 칸당 49px, 탭 글씨를 줄여야 함 |
| C | 5칸: 규칙 → 상점 1칸, 보상은 상점 안 구역 | 86 | 보상과 상점이 한 탭에 섞여 다시 길어짐. '상점'이라는 이름에 출석·과제가 숨음 |
| D | 5칸 유지 + 홈 위 띠 강화 | 70 | 이번 요청(메뉴로 나누기)과 반대 |

**결정: A.** 규칙은 머리줄 `?`(44px, aria-label '규칙', 선택되면 aria-current) + 홈의 '규칙 한눈에' 카드에서도 들어감. 규칙 화면 맨 위에 `‹ 규칙`(직전 탭으로 돌아감). 서버가 없을 때(fbmode 아님)는 친구만 숨고 5칸.

### 2-2. 받을 보상 알림(띠 vs 배지)
| 안 | 점수 |
|---|---|
| 홈 띠 유지 + 배지 | 84: 홈이 다시 무거워지고 같은 정보가 두 곳 |
| **보상 탭 숫자 배지(모든 화면의 탭 줄·PC 머리줄) + 보상 탭 맨 위에 '받을 보상 n · 출석체크 외 4개 [모두 받기]' 띠(받을 것이 있을 때만)** | **96**: 어느 화면에서든 보이고 홈은 대국만. 배지는 로컬 값으로 2초마다 다시 셈(서버 읽기·쓰기 0) |

### 2-3. 이름 정리('상점'과 겹치지 않게)
꾸미기 → **상점**(탭·화면 제목) / 교환소 → **상품** / 보관함 → **보관함**(상점 안 두 번째 버튼) / 과제(시트 탭) → **보상 탭의 '오늘의 과제'**. '교환소'·'꾸미기'라는 글자는 화면·aria에서 0개(gd3func로 확인).

### 2-4. '교환소나'(말이 끊긴 요청) 해석
"교환소도 같이 정리하라"로 봄 → 교환소를 '상점' 안의 '상품'으로 흡수(같은 뜻의 이름이 셋이던 문제 해결). 근거: 사용자가 바로 앞에서 '꾸미기→상점'을 요청했고, 교환소는 그 상점의 상품 목록이므로 따로 남길 이유가 없음.

### 2-5. 상점 화면(사용자 추가 요청: "상품이 늘어나면 보기 어렵다")
첫 화면 = 분류 버튼 7개(그림·이름·'3개 · 보유 1' / 보관함은 '보유 n · 장착 중 이름') → 누르면 그 분류 목록(‹ 뒤로). 분류당 20~30개도 3~4열 격자로 한 분류씩. 상품·보관함 같은 구조. 앞으로 이용권 등 다른 상점 항목은 같은 분류 버튼으로 추가하면 됨. PC: 왼쪽 열(내 모습 미리보기·상품/보관함), 오른쪽 목록만 안쪽 스크롤.

### 2-6. 돌 무늬·판 테마 공개(사용자 요청)
ECO_PUB에 w·b 추가. 돌 = 흑(A)·백(B) 각자 자기 무늬(두 화면 같음). 판 테마 안 비교:
| 안 | 점수 |
|---|---|
| 방장 판 | 80: 방장만 유리 |
| 흑(선 시작) 플레이어 판 | 82: 동전으로 정해져 한쪽만 늘 손해 볼 수 있음 |
| **장착한 사람 것, 둘 다 장착이면 대국 번호(gid)로 한 사람(두 폰이 같은 답, 판마다 약 반반)** | **95** |
AI·봇 대국은 내 돌만 내 무늬. 규칙 eqPub은 보유 여부만 보므로 그대로 통과(시험: 보유한 무늬 공개 허용·없는 판 거부) → **firestore.rules 사본 수정 없음.** 설명 문구: '양쪽 화면 내 돌에 보여요', '양쪽 화면 판에 보여요'(판 분류 안에 '둘 다 쓰면 판마다 한 사람 것').

## 4. 진행 중 추가 요청 처리
1. 홈 '최근' 카드 없앰(요소 제거, renderRecent는 요소가 없으면 그냥 돌아감).
2. PC 2560: 상점은 탭이라 묻히지 않음(`shots/after/q1400_dark_shop*.png`).
3. 머리줄 옥돌(늘 보임, 누르면 상점) + 머리줄 고정(스크롤해도 보임). 닉네임이 잘리면 '베팅 오목' 글자만 숨기고 로고는 남김(hdrFit).
4. 베팅 단위 '칩': `const PTU='칩'` 한 줄 + `jo()`(을/를·이/가·은/는·과/와·으로/로, 숫자·영문 끝소리 처리) + `ptT()`(문구 속 `{P}`, `{P을}` 등). HTML 고정 문구는 `data-ptu` 붙은 요소를 시작할 때 채움.
   - 사용 위치: 규칙 탭(매 턴 +10칩·상대 칩 비공개·1칩씩·규칙 전문 5줄), 처음 화면 문구, 규칙 요약(RULES_MINI), 베팅 판(남은 칩·칸마다 1칩 이상·n칩 초과·되돌리기/+5/+10 aria), 시간 초과 문구 2곳, 결과 '쓴 칩', 요령 문구, 튜토리얼 3단계, 상대 칩 비공개(aria·토스트), 복기 'AI라면?' 기준, 분석 카드 3곳, 묘수(내 칩·상대 칩·합·해설·버튼 aria), 옥돌 안내 1곳.
   - **랭크 점수(티어 점수·랭킹 1849 등)는 그대로 둠 → 랭크 점수도 바꿀지 사용자 확인 필요.**
5. 묘수 해설: '상대가 A·B·C를 다 가져야 오목 / 같으면 내 돌(내가 후 플레이어) / 상대는 칸마다 내 칩보다 1칩 더 필요 / 1·1·22를 걸면 상대는 2+2+23 = 27칩 필요 / 상대는 26칩뿐 → 막힘 / 그래서 합 24칩이 최소', 정답 줄 '정답 합 24칩 (예: 1·1·22)'. 판정(pzJudge)은 그대로.
6. PC 동전: 연출은 PC에서도 돌고 있었으나 128px 고정이라 넓은 화면에서 거의 안 보였음 → 무대 확대. 프레임 `shots/coin/`(폰·1280·1920·2560).
7. PC 대국 화면 재점검(복기·AI라면?·이모트·결산·승급 창): `shots/after/game/` 0건.
