## 1. 재화 설계

### 1-1. 이름 원칙 (헷갈림 방지)

| 이미 있는 것 | 화면 표시 | 비고 |
|---|---|---|
| 판 안에서 매 턴 +10 받고 거는 것 | **점수** (지금 그대로) | 대국 화면에만 나옴 |
| 랭크 티어를 정하는 숫자 | **랭크 점수** (지금 '점수' → '랭크 점수'로 바꾸기 제안) | 랭크 탭에만 나옴 |
| 새 재화 | **구슬**, **출석체크** | 대국 화면에는 표시하지 않음 |

- 쓰지 않는 이름: 점수·포인트(판 점수와 겹침), 칩·코인·머니·엽전(도박·돈 느낌, '베팅'이라는 게임 이름과 합쳐지면 사행성으로 오해받기 쉬움), 돌·칸(판의 돌·칸과 겹침).
- '구슬'은 둥근 바둑돌과 어울리고, 돈 느낌이 적습니다. '출석체크'은 출석 출석체크처럼 "모으면 한 칸 열린다"는 뜻이 바로 전달됩니다.
- 이름 후보(사용자 선택용): 구슬 / 옥구슬 / 별가루, 출석체크 / 발자국.

- 챌린저 자리에 AI 상대가 있을 수 있음(지금 AI 상대 100명 중 마스터대 6명). **보상은 사람에게만** 주고, 순위 표시는 지금 방식 그대로. AI 때문에 사람이 챌린저에서 밀리는지는 랭크팀이 정할 일로 넘김(4-3).
- 마스터·챌린저: 관리자 마감 때 "AI 상대 판만으로 90% 넘게 이긴 계정"은 표시해서 사람이 한 번 보고 확정(위조 대응, 3-4). 조건을 더 강하게(예: 사람 대국 5판 이상) 할지는 사용자 결정.

- 실버는 배치 완료로 대신(시작 1,000점이 실버라서). 브론즈로 배치돼도 배치 보상 50은 같음.
- 떨어졌다가 다시 올라가면 0(같은 시즌 같은 티어는 한 번만).
- 시즌이 바뀌면 소프트 초기화(한 단계 아래 티어 최저점)로 다시 올라가며 또 받음 — "다시 오르는 재미"가 보상이 됩니다.
- 승급 보상은 **구슬·출석체크만**. 남에게 보이는 테두리·칭호는 시즌 종료 기록(관리자 기록)으로만 줍니다(위조 대응).

### 2-3. 지급 시점 — 랭크팀 시즌 문서(cfg/season{n})와 맞물리기

```
시즌 끝(3·6·9·12월 1일 0시, 한국 시각)
 │ 랭크 점수 계산 멈춤(그 시각 이후 결과는 다음 시즌)
 │ 12시간 유예: 늦게 들어온 결과·한쪽 기록 검증(지금 10분 대기 + 방 기록 재계산)이 끝나기를 기다림
 ▼
관리자 폰 "시즌 마감" 버튼(1일 정오 이후)
 │ 같은 계산(rankCompute)으로 최종 순위 → 사람 계정만 골라
 │ cfg/season{n} 한 문서에 기록:
 │   final: true · at: 마감 시각 · t: { uid: 티어코드(0~6) } · top: [챌린저 uid 3개]
 │   amt: [200,400,700,1000,1400,1800,2500]   ← 보상 구슬표
 │   (랭크팀이 쓰는 다음 시즌 시작 점수도 같은 티어코드로 정해짐: 코드 → 한 단계 아래 최저점)
 ▼
각 폰: 앱 열 때 cfg/season{n} 1번 읽고 폰에 영구 저장(읽기 1회)
 │ 내 uid가 있으면 홈에 "시즌 n 보상 받기" 카드
 ▼
받기 → prof(구슬·테두리) + clm/{uid}_s{n}(받음 표시) 한 번에 쓰기
       규칙이 cfg/season{n}을 직접 읽어 금액·티어가 맞는지 확인
```

- 한 문서로 **보상**과 **다음 시즌 시작 점수**를 같이 정하므로, 두 팀 결과가 어긋날 수 없습니다.
- 크기: uid 한 명당 약 35바이트 → 문서 한도(1MiB)로 약 2만 5천 명. 2만 명이 넘으면 cfg/season{n}_1, _2로 나눔.
- 관리자가 마감을 늦게 누르면: 보상 카드에 "집계 중이에요"라고 표시. 마감 전에는 지난 시즌 테두리를 아무도 받지 못함(공정).
- 마감 문서는 한 번 쓰면 고칠 수 없게(규칙) — 단, 실수 대비로 **마감 후 24시간 안 1회 수정**만 허용하는 안을 랭크팀에 제안.

## 3. 1단계 구현 범위 (서버 없이, 지금 Spark 요금제 그대로)

### 3-1. 만들 것 (할 일 목록)

1. **재화 표시**: 홈 상단 오른쪽에 `● 구슬 1,240`(5장 화면 참고). 대국 화면에는 표시 안 함.
2. **지갑 저장**: 이미 있는 내 프로필 `prof/{uid}`에 칸 추가 — 구슬 잔액, 오늘 날짜·오늘 받은 양, 이번 주·이번 주 받은 양, 출석체크(시즌 번호·개수·받은 단계), 보유 꾸미기 목록, 장착 정보, 마지막 쓴 시각(서버 시각).
3. **1회성 보상 표시 문서** `clm/{uid}_{종류}`: 만들기만 가능, 수정·삭제 불가. 종류 = `s3`(시즌3 보상), `p3_4`(시즌3 다이아 첫 승급), `a_ult`(Ultimate 첫 승 업적) 등.
4. **가격표 문서** `cfg/shop`: 관리자만 씀. 상품 id → 구슬 가격. 규칙이 결제할 때 이 값과 대조.
5. **시즌 길 표** `cfg/road{n}`: 관리자만 씀. 단계별 구슬·꾸미기.
6. **남에게 보이는 꾸미기**: 이미 쓰는 랭크 결과 문서(`res`, `bres`)에 장착 정보 `eq`(짧은 id 몇 개)를 같이 실음. 랭킹 화면은 이 문서들을 이미 읽고 있으므로 **추가 읽기 0회**. 규칙은 쓸 때 "내 prof의 보유 목록에 있는 것만" 허용.
7. **교환소·보관함·보상 화면**(5장).
8. **결과 화면 한 줄**: 랭크 점수 변동 아래 `+12 구슬 · +2 출석체크`.
9. **게스트(익명) 계정**: 구슬은 똑같이 쌓이되, "구글 계정을 연결해야 기기를 바꿔도 남아요" 안내(업적 50구슬로 연결 유도). 랭크 보상은 원래 구글 계정만(랭크전이 구글 계정 전용이므로).
10. **랭크팀에 요청**: res/bres에 `eq` 칸 허용, cfg 규칙에 `season{n}`·`shop`·`road{n}` 허용, '랭크 점수' 표기.

**하지 않는 것(1단계)**: 결제·광고·뽑기·선물/거래·서버 함수·상품 기간 한정·푸시 알림.

### 3-2. 규칙으로 지킬 수 있는 것 / 없는 것 (정직하게)

| 지킬 수 있음 (규칙이 막아 줌) | 어떻게 |
|---|---|
| 내 지갑은 나만 바꿈, 남의 것은 못 건드림 | `uid == me()` |
| 잔액이 음수·상한 초과 불가 | `gem is int && 0 <= gem <= 99999` |
| **하루 획득 상한 150, 주간 100** | 서버 시각(`request.time`)으로 오늘 날짜 번호를 계산해 "오늘 받은 양 + 이번 증가분 ≤ 150"을 검사. 날짜가 바뀌면 0부터 |
| 출석체크 하루 20, 시즌이 바뀌면 0 | 같은 방식(날짜 번호·시즌 번호를 서버 시각으로 계산해 대조) |
| 1회성 보상(시즌·승급·업적·시즌 길 단계)을 두 번 못 받음 | 같은 쓰기 안에서 `clm` 문서가 새로 생겨야만 증가 허용(`existsAfter`, 기존에 없어야 함). clm은 삭제 불가라 prof를 지우고 다시 만들어도 재수령 불가 |
| 시즌 보상 금액·테두리가 관리자 기록과 같음 | 규칙이 `cfg/season{n}`을 읽어 내 티어코드의 금액과 비교 |
| 상품은 정해진 가격으로만 삼 | 규칙이 `cfg/shop`의 가격을 읽어 "잔액 감소 = 가격, 보유 목록에 그 상품 1개 추가"를 검사 |
| 남에게 보이는 꾸미기는 실제로 가진 것만 | res/bres 쓸 때 규칙이 내 prof 보유 목록을 읽어 확인 |
| prof를 지웠다 다시 만들어 잔액 부풀리기 | 새로 만들 때 잔액은 하루 상한 이하로만 시작 가능 |

| 못 지킴 (서버 없이 불가능) | 피해와 대응 |
|---|---|
| **실제로 대국을 했는지·이겼는지** — 규칙은 판 결과를 모름 | 조작하면 대국 없이 하루 150·주 100까지 받을 수 있음. 열심 유저와 같은 속도일 뿐, 그 이상은 불가. 얻는 것은 꾸미기뿐이라 다른 사람 피해 없음 |
| 첫 승급·업적 1회성 보상의 **조건 충족 여부** | 각각 한 번씩만 위조 가능(승급 최대 1,100/시즌, 업적 최대 850/평생). 남에게 보이는 보상은 여기서 주지 않음 |
| **랭크 점수 자체** — 각 폰이 계산하고, AI 상대 결과(bres)는 본인이 써서 거짓 가능 | 시즌 보상은 랭크 점수를 믿을 수밖에 없음. 대응: 관리자 마감 때 이상 계정(AI 판만 90% 넘게 승) 표시 후 사람이 확인, 마스터 이상은 확인 후 확정. 완전히 막으려면 2단계 서버 필요 |
| 관리자 폰 계산이 맞는지 | 관리자 본인의 책임. 마감 결과(티어별 인원)를 랭크 탭에 공개해 누구나 자기 폰 계산과 비교 가능 |
| 내 화면에서만 보이는 조작(코드 고쳐서 혼자 보기) | 막을 수 없고, 막을 필요도 없음(남에게는 규칙 통과한 것만 보임) |

> 결론: 1단계 재화는 **"위조돼도 혼자 꾸미기를 빨리 모으는 정도"**로 피해를 묶어 둡니다. 그래서 1단계에서는 재화로 **랭크·대국에 영향 주는 것을 절대 팔지 않습니다.** 돈이 오가는 2단계부터는 서버 검증이 필수입니다(4장).

### 3-3. 규칙 모양 (구현 팀 참고용 제안, 실제 적용 전 Firebase 콘솔 '규칙 플레이그라운드'로 시험 필요)

```
// prof/{uid} 갱신 중 "구슬 획득" 경우만 발췌한 초안
function today() { return math.floor((request.time.toMillis() + 32400000) / 86400000); } // 한국 날짜 번호
function earnedToday(o) { return o.get('gd', -1) == today() ? o.get('gc', 0) : 0; }
function gemEarnOk(o, n) {
  let d = n.gem - o.get('gem', 0);
  return d > 0 && n.gd == today() && n.gc == earnedToday(o) + d && n.gc <= 150
    && n.at == request.time;
}
function claimOk(o, n, cid, amt) {           // 1회성 보상
  return !exists(/databases/$(database)/documents/clm/$(cid))
    && existsAfter(/databases/$(database)/documents/clm/$(cid))
    && n.gem - o.get('gem', 0) == amt;
}
// 시즌 보상 금액: get(/cfg/season{n}).data.amt[ get(/cfg/season{n}).data.t[me()] ]
```

- 확인 필요(정직하게): 규칙 안의 나눗셈·`math.floor` 동작, 한 요청당 `get/exists` 횟수 제한(문서 읽기 10번 안팎)에 걸리지 않는지는 **실제 플레이그라운드 시험으로 확인**해야 합니다. 걸리면 "획득"과 "소비"를 다른 쓰기로 나눕니다.
- 지금 규칙의 prof는 키를 `nick, airec, pts`로만 허용하고, cfg는 `master`만 허용하므로 둘 다 늘려야 합니다(랭크·규칙 담당과 한 번에).

### 3-4. 무료 요금제(Spark) 부담

| 늘어나는 것 | 양(하루 대국 300명 × 8판 가정) | 무료 한도 |
|---|---|---|
| 대국 끝 prof 쓰기 | 약 2,400 쓰기 | 쓰기 20,000/일 |
| 규칙의 prof·cfg 확인 읽기 | 약 2,400~4,800 읽기 | 읽기 50,000/일 |
| 시즌 문서·가격표 읽기 | 사람당 시즌 1번 + 가격표는 폰에 저장(버전 바뀔 때만) | |
| 꾸미기 표시 | 0 (이미 읽는 res/bres에 실음) | |

- 다른 기능(랭킹 계산이 res/bres 전체를 읽는 것 등)과 **같은 한도를 나눠 쓰는** 점이 진짜 위험입니다. 재화 몫은 쓰기의 약 12%, 읽기의 약 10% 이하로 잡았습니다.

- **구슬을 팔지 않는 이유**: 구슬을 돈으로 살 수 있게 되면 구슬로 사는 모든 물건이 '간접 유상 구매'가 되어, 만약 나중에 무작위 요소가 하나라도 생기면 확률 표시 의무 대상이 됩니다. [출처 1] 그리고 "돈으로 시간 단축"은 사용자가 원하지 않는 현질 유도 방향입니다.
- 나중에 정말 유료 재화가 필요하면: 이름을 따로(예: **옥**), 지갑도 따로(`ent/{uid}` 서버 전용), 구슬과 서로 바꾸지 않음 → 1단계 구조를 고치지 않고 덧붙일 수 있음.
- 수익 예상: 이용자 수·광고 단가를 모르는 상태라 숫자는 만들지 않았습니다. 출시 후 계산식: 광고 수익 = 하루 광고 노출 수 × 광고 단가(eCPM)/1000, 판매 수익 = 판매액 × (1 − 수수료).

### 4-4. 결제 검증 서버와 비용

```
폰(TWA 앱)                             Firebase (Blaze 요금제)
 ① Digital Goods API로 상품·가격 조회
 ② Payment Request API로 구매 ──▶ 구글 플레이 결제창
 ③ 구매 토큰 받음 ───────────────▶ Cloud Functions "구매 확인"
                                      ├ Play Developer API로 토큰 진짜인지 확인
                                      ├ 3일 안에 승인(acknowledge) ← 안 하면 자동 환불
                                      └ ent/{uid}에 권리 기록(서버만 쓰기, 규칙: 사용자 쓰기 금지)
 ④ 앱이 ent/{uid}를 읽어 광고 끄기·유료 줄 열기
                                   Cloud Functions "환불 알림"(Play 실시간 알림)
                                      └ 환불·취소되면 ent에서 권리 회수
```

- TWA에서 디지털 상품을 팔려면 Play 결제를 써야 하고, Digital Goods API + Payment Request API로 구현하며, 구매 확인·승인은 **반드시 서버에서**, 3일 안에 승인하지 않으면 구글이 환불·회수합니다. 크롬 101 이상 필요. [출처 2]
- Cloud Functions는 **Blaze(종량제)에서만** 쓸 수 있고, 결제 계정(카드) 연결이 필요합니다. [출처 4]

| 항목 | 무료 사용량 | 넘으면 | 예상(작은 규모) |
|---|---|---|---|
| Cloud Functions 호출 | 월 200만 회 | 100만 회당 0.40달러 | 구매·환불 몇백~몇천 회/월 → 0원 |
| Functions 계산 시간 | 월 40만 GB-초, 20만 CPU-초 | Google Cloud 요금 | 0원 |
| Firestore | 읽기 5만·쓰기 2만·삭제 2만/일, 저장 1GiB (Spark와 같음) | 10만 읽기당 0.03달러, 10만 쓰기당 0.09달러(기본 요율 표기, 서울 요율은 확인 필요) | 지금과 같음 |
| 함수 배포 이미지 저장 등 부대 비용 | 확인하지 못함 | — | 몇백 원 수준일 가능성, **출시 전 확인 필요** |

[출처 4·5·9]

- **비용이 생기는 시점**: Blaze로 바꾸는 순간이 아니라, 무료 사용량을 넘을 때부터. 다만 Blaze는 **예산 알림이 사용을 멈춰 주지 않으므로** [출처 4], 예산 알림(예: 월 5,000원)을 걸고, Firebase가 권장하는 Functions 지출 상한(spend cap) 설정도 같이 합니다.
- **지금(결제 없음)은 Blaze로 바꿀 필요가 없습니다.** 바꾸는 시점 = 광고 제거 상품을 팔기로 정한 때.
- 서버가 생기면 덤으로 할 수 있는 것: 시즌 마감을 관리자 폰 대신 예약 함수로, 대국 결과 검증 후 구슬 지급(1단계의 "안 놀고 받기" 차단). 필수는 아님.

### 4-6. 공정성 원칙 (돈 써도 랭크 유리 없음)

1. 돈·광고로 얻는 것은 **모양**(꾸미기·연출·배지)과 **광고 안 보기**뿐.
2. 판 점수, 베팅, 시간 설정, 매칭, 랭크 점수 계산, AI 단계 해금, 복기 정보는 결제와 무관 — 설정 화면에 이 문장을 그대로 공개.
3. **티어·시즌 보상 테두리와 칭호는 팔지 않음.** 유료 꾸미기는 티어 색·모양과 헷갈리지 않게 디자인 규칙을 둠(티어 색 6가지 사용 금지).
4. 상대 화면에 보이는 꾸미기는 심리전 정보를 주지 않음(봉인 인장 크기·시간 고정, 돌 무늬는 상대 설정이 켜져야 보임).
5. 무작위 상품 없음. 기간 압박 판매 없음. 결제 유도 팝업 없음(상점은 사용자가 들어갈 때만).
6. 무료 유저가 시즌 길 무료 줄로 얻는 구슬·꾸미기는 유료 줄이 생겨도 줄이지 않음.

### 수정

- 경제: 단계당 출석체크 40개로(보통 35단계, 열심 11주차 완주 — 계산 스크립트로 확인), 한 폰 대국 보상 0, AI 보상 낮춤(승 6), 일반 게임 같은 상대 하루 6판째부터 0, 승급 보상은 구슬·출석체크만으로.
- 수익화: 유료 재화 삭제 → 원화 직접 판매(광고 제거·유료 줄·세트·응원), 광고 표(위치·3판에 1번·5분·첫 3판 없음), 순서를 광고 → 광고 제거 → 유료 줄로.
- 법무: 무작위 요소 전면 삭제, 이름 금지 목록, 체크리스트 13항(현재 해당 없음 표시), 확인 못 한 3가지는 "확인 필요"로 명시, 출처 번호 달기.
- 기술: 1회성 보상을 삭제 불가 `clm` 문서 + `existsAfter`로, 꾸미기 표시를 이미 읽는 res/bres에 실어 추가 읽기 0, prof 새로 만들 때 잔액 상한, 규칙 시험 필요 사항을 정직하게 표기, Spark 부담표 추가.
