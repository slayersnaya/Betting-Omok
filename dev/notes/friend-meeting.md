# 친구 기능 — 팀 회의록

참석: UX 기획/디자인 · 프론트엔드 · 백엔드(Firestore 규칙·데이터) · QA/보안·안전
대상: `/home/claude/eval/friend/src/index.html`(base.html 기준), `firestore.rules`, `fb-adapter.js` 사본, 가짜 Firebase `fake/fs.js` 끝에 덧붙인 블록

## 1. 요구 정리
- 원문: "친구 추가랑 친구 초대 기능 만들어줘. 친구랑 대화도 할 수 있게, 아무튼 친구 기능."
- 추가 요구(작업 중 받음)
  1. 접속 여부(초록 점·대국 중·"5분 전/어제"), 친구 프로필(티어·점수·순위·시즌 전적·연승/연패·나와의 전적), 랭킹에서 누구든 프로필 + 친구 추가
  2. 검색: 닉네임 정확·앞부분(입력 중), nicks에 표시용 닉네임, AI 상대도 같은 모양으로 검색·프로필, AI에게 요청하면 자연스럽게
  3. 친구 초대 = 앱 안 버튼으로 카톡 등에 링크 공유(Web Share, 없으면 링크 복사), `?f=코드` 링크, 받은 사람은 설치 안내 → "친구 할까요?" → 바로 친구. 방 링크 공유도 같은 방식
  4. 대국 신청(필수): 친구 줄·프로필·대화 세 곳, 시간 설정 고르기, 받는 쪽 위 알림 [수락]·[거절], 보낸 쪽 기다리는 중·취소, 2~3분 만료, 대화에 기록, 대국 중·차단·도배 처리

## 2. 설계 비교 → 결정

| 주제 | 안 A | 안 B | 결정과 이유 |
|---|---|---|---|
| 들어가는 곳 | 머리줄 아이콘 + 시트 | 로비 5번째 탭 '친구' | **B**. 목록·요청·설정이 한 화면에 다 들어가고 배지가 늘 보임. 넓은 화면 머리줄도 1024px에서 겹치지 않음(스크린샷 확인) |
| 관계·대화 저장 | 관계 문서 + 메시지 하위 컬렉션(메시지마다 문서) | 두 사람마다 문서 하나 `fp/{a_b}`에 관계 + 최근 대화 50개 | **B**. 메시지 1개 = 쓰기 1번, 친구 목록 구독 하나로 안 읽은 수·대국 신청까지 받음, 오래된 메시지 지우기 비용 0(배열 앞이 빠짐). 규칙이 "지난 목록 + 하나"·1초 간격을 검사할 수 있음. 대신 대화는 최근 50개만 남음 |
| 접속 표시 | 기존 `rt/lobby`(매칭 때만 씀, 20초마다 쓰기) | 새 `on/{uid}` 10분마다 + 바뀔 때 | **B**. rt/lobby는 매칭 중에만 쓰여 접속 판단에 못 쓰고, 20초 하트비트는 무료 한도에 맞지 않음 |
| 접속 정보 공개 | 누구나 | 친구만(규칙) | **친구만**. 모르는 사람이 접속 시각을 보지 못함(미성년자 고려). AI·모르는 사람 모두 '정보 없음'으로 같게 보여 AI가 티 나지 않음 |
| 초대 링크 | 코드만(받은 사람이 요청) | 코드 + 토큰(7일, 주인만 발급) | **둘 다**. 토큰이 맞으면 수락 즉시 친구, 오래되거나 없으면 일반 요청. 코드는 검색으로 보일 수 있어 코드만으로 바로 친구가 되면 안 됨 |
| 게스트 | 허용 | 구글 연결자만 | **구글만**(규칙 `google()`). 탭에서 연결 안내, 지금 기록 그대로 이어짐 |
| AI에게 요청 | '요청 보냄'으로 남기고 수락 안 함 | "친구 요청을 받지 않는 사용자예요" | **B**. 실제로 '친구 요청 받기'를 끈 사람·나를 차단한 사람에게 요청해도 같은 문구가 나오므로 거짓 문구가 아님. 영원히 대기하는 가짜 상태를 만들지 않음. AI 채팅 응답은 만들지 않음 |
| 거절 | 문서 삭제 | `st:'no'` 남김 | **no**. 삭제하면 요청한 쪽이 곧바로 다시 보내 괴롭힐 수 있음 → 7일 뒤에만 다시 요청(규칙) |
| 대국 신청 | 받는 사람 수신함 문서 하나 | 친구 문서의 `ga/gb` | **친구 문서**. 이미 구독 중이라 추가 읽기 없음. 한 번에 하나, 신청자가 방장인 열린 방만(규칙), 3분 만료 |
| 공유 | 카카오 JS SDK | Web Share API, 없으면 링크 복사 상자 | **Web Share**. 카카오 SDK는 앱 키 등록이 필요 → 나중 선택지 |

## 3. 데이터 구조·규칙 요약

| 문서 | 내용 | 읽기 | 쓰기(규칙) |
|---|---|---|---|
| `fp/{a_b}` (a<b) | a, b, by, st(req/ok/no), at·sa(서버 시각), na·nb(닉네임), tk, m[≤50]{i,s,t(1~200자),a,e 반응,k 대국 기록}, q, ra·rb(읽은 번호), wa·wb(마지막 보낸 서버 시각), ga·gb{gid,at,t} | 두 사람 | 만들기: 구글·본인 포함·양쪽 차단 없음·상대가 요청을 받음(또는 토큰 일치→바로 ok). 고치기: 수락·거절·7일 뒤 재요청·내 닉네임·메시지 1개 추가(번호 +1, 내 칸, 1초 간격, 앞부분 그대로)·읽음(앞으로만)·대국 신청(내가 방장인 열린 방, 한 번에 하나)·받은 신청 지우기. 지우기: 친구 끊기·내 요청 취소·내가 거절한 기록·내가 차단한 상대 |
| `on/{uid}` | at(서버 시각), st(on/off/g/r), fc, tk·tka, nr(요청 안 받기), hs(상태 숨김) | 본인·친구만 | 본인·구글, 키·형식 제한, 코드는 fc 주인 확인 |
| `fc/{코드}` | by, n | 로그인 | 주인만, 8자(I·O·0·1 없음) |
| `bk/{나_상대}` | by, who, nk, at | 차단한 사람만 | 본인만 만들기·지우기(차단당한 사람은 모름) |
| `rep/{나_시각}` | by, who, nk, why(4종), txt(최근 대화 20개 사본 ≤2000자), at | 관리자만(`isAdmin()`) | 본인 이름으로 만들기만 |
| `nicks/{key}` | 기존 by·g·at + **n**(표시용, 12자) | 로그인 | 키 목록에 n 추가. 앱이 `nickKey(n) == 문서 id`를 다시 확인 |

- 앞부분 검색: nickKey가 UTF-8 hex라 앞부분 hex가 곧 문서 id 앞부분 → `where('__name__','>=',key)` + `<key+'g'` + `limit(12)`. 어댑터 사본이 `'__name__'`을 `documentId()`로 바꿈(3줄). 2글자부터, 0.35초 디바운스, 2분 캐시(짧은 앞부분 결과가 12건 미만이면 그 안에서 거름 → 추가 읽기 없음). AI 이름은 `BOTS`에서 그대로 찾아 같은 줄 모양으로 섞음.
- 프로필 숫자는 `RK.map.get(seat)`의 r·g·w·l·d·ws·ls를 읽기만 함(rankCompute·gainOf·emblem·tierMove 수정 없음). 나와의 전적 = res(랭크) + bres(AI 랭크) + 이 기기 지난 대국(일반 대국 포함), 판 id로 중복 제거.
- 랭킹 줄·시상대에 `data-act="prof"`만 붙임 → 누구나 프로필, 친구 추가 버튼.

## 4. 화면 흐름
- 친구 탭: 찾기(닉네임·코드) → 결과 줄 [추가]/[수락]/요청함/대화 · 내 친구 코드 [복사] · [친구 초대] / 친구 요청(받은·보낸) / 친구 목록(접속 점·"대국 중"·"N분 전 접속"·티어·점수, [대국 신청][대화+안 읽은 수]) / 친구 설정(요청 받기·접속 상태 보이기·대국 중 알림 배지만/끄기·차단 목록·안전 안내 3줄)
- 프로필 시트: 문양·닉네임·접속 / 티어·점수·순위 / 시즌 랭크전 W승 L패 D무 · 연속 / 나와의 전적 / [대화][대국 신청] 또는 [친구 추가]·[수락] / 친구 끊기·차단·신고
- 대화 시트: 머리(문양·닉네임·상태, 대국 신청, ⋯ 메뉴) · 안전 안내 · 날짜 줄 · 말풍선(내 것 '1'·'읽음') · 반응(친구 말풍선 누르면 5개) · 대국 신청 기록 줄 · 입력(200자, 링크·전화번호 막음, 욕설 별표)
- 대국 신청: 시간 고르기(일반 게임 프리셋 4개) → 숨긴 방 생성 → 보낸 쪽은 방에서 "○○님 기다리는 중 · 2:56 남음 [취소]" / 받는 쪽 로비 위 "○○님이 대국을 신청했어요 [거절][수락]"(대국 중이면 배지만, 로비로 오면 알림). 수락 → 그 방 자동 참가. 거절 → 보낸 쪽 "○○님이 거절했어요" 후 방 정리. 3분 → 닫고 방 정리. 상대가 대국 중이면 먼저 "지금 대국 중이에요… 그래도 신청". 같은 친구 10분에 3번까지(앱) · 동시에 하나(규칙)
- 링크: `?f=코드&k=토큰`(옛 `#f-`도 받음). web-install.js는 앱 안 브라우저→크롬 이동 때 `inst=1`만 붙이고 다른 쿼리는 그대로 둠(코드로 확인) → `f`·`k` 유지. 받은 코드는 7일 동안 이 기기에 보관 → 닉네임·구글 연결 뒤 "○○님과 친구 할까요?" [친구 하기]
- 대국 중 알림: 화면 위 말풍선 배지만(소리·팝업 없음), 랭크전 중에는 숫자 없이 점, 설정에서 끄기

## 5. 무료 한도 하루 추정(가입 1000명)

## 7. 수정
- UX: 링크는 읽기 전용 입력칸(한 줄, 눌러서 전체 선택), 말풍선 `keep-all + text-wrap:pretty`, 머리줄 배지를 글자 옆으로, 보낸 쪽 기다리는 중 알림을 위쪽(상대 막대 자리)으로, 안내 문구를 "링크를 받은 친구가 열면 바로 친구가 돼요" 한 문장으로, 아이콘 버튼에 title
- 프론트: `dialog()` 첫 줄에 `d.inert=false`(1줄), 보낸 메시지를 4초 동안 서버 목록에서 확인하고 없으면 다시 보냄, 테스트 포트 분리(8791·8792·8794)
- 백엔드: 규칙 `fpInvite`에 "지금 신청이 없을 때만" + `t`(시간 설정 0~3), 메시지에 `k`(inv/acc/dec/can/exp), 접속 표시 15초 안정 후·앱 전환 60초 유예·닫을 때 바로, 읽음 10초에 한 번, 하루 메시지 300개(앱)
- QA: friendtest에 대국 신청 수락·대국·끝/거절/취소/3분 만료/연속 제한/남의 방 신청 거부 추가, 테스트 중계가 fp 메시지를 서버처럼 한 줄로 검사(낡은 목록 거부·되돌림 — 실제 Firestore와 같은 동작)

## 9. 한계(정직하게)
- **앱이 닫혀 있으면 알림이 안 옴.** Spark에는 서버 코드·푸시 서버가 없음. 앱을 열면 배지·알림으로 보임. 나중 방안: Blaze + Cloud Functions + FCM 웹 푸시(설치한 앱에서만, 아이폰은 홈 화면 앱 16.4 이상).
- 대화는 친구마다 최근 50개만 남음. 친구를 끊으면 대화도 지워짐(신고하면 최근 20개 사본이 관리자에게 감).
- 욕설·링크·전화번호 거르기는 앱에서만 함. 고친 앱으로 보내면 저장은 되지만, 받는 쪽 화면에서는 다시 가려서 보여 줌.
- 규칙은 실제 Firebase 서버(에뮬레이터)로 돌려 보지 못했음. 같은 내용을 JS로 옮긴 가짜 Firebase로만 확인. 목록 자르기(`list[a:b]`)·계산한 키(`map['w'+s]`)는 공식 규칙 문법이지만, 게시 전 콘솔의 규칙 놀이터로 한 번 확인 권장.
- 웹 ↔ 설치한 앱 저장소: 안드로이드 크롬은 웹과 설치 앱이 저장소를 같이 써서 링크 코드가 이어짐. 아이폰은 홈 화면 앱 저장소가 사파리와 따로라 설치 후에는 이어지지 않을 수 있음 → 앱에서 링크를 다시 열거나 친구 코드를 입력하면 됨. 보관은 7일.
- 접속 표시는 최대 13분 늦을 수 있음(10분 하트비트). 앱을 강제 종료하면 '접속 중'이 잠깐 남음.
- 지난 시즌 최종 티어는 표시하지 않음(지금 시즌 1). 랭크 개편팀의 시즌 기록(cfg/season{n})이 합쳐지면 프로필 칸 하나로 연결 가능.
- 받은 요청의 닉네임은 nicks 문서 주인과 대조해 다르면 '닉네임 확인 안 됨'으로 표시(완전한 서버 검증은 아님).
- 동시에 보낸 메시지는 서버가 하나를 거부하고 앱이 다시 보냄 → 아주 드물게 순서가 바뀜.
- 카카오톡 전용 공유(카카오 JS SDK)는 앱 키 등록이 필요해서 이번엔 하지 않음(나중 선택지).
- 병합 주의: ① 다른 팀이 공용 어댑터에 이메일 로그인을 넣는 중 — 이메일 계정도 친구 기능을 쓰게 하려면 규칙의 `google()`을 그 팀의 '연결된 계정' 함수로 바꿔야 함. ② `renderRank`의 랭킹 줄·시상대 두 줄에 `data-act="prof"`를 붙였음(랭크 개편팀과 겹치는 줄). ③ 테스트용 fbtest.py는 이미 예전 화면(#sh-acc) 기준이라 base에서도 랭크 관문 단계에서 멈춤.
