## 1. 복기 "AI라면?" 비교
- 설계: 끝난 판 복기에서 턴마다 "Ultimate가 내 자리라면 A·B·C에 몇·몇·몇"을 내 베팅 바로 아래에 같은 칩 색으로 표시(▲▼ = 나보다 많이/적게). 선 턴이면 Ultimate가 골랐을 세 칸을 판 위 점선으로 표시.
- 결정: 입력은 내 입장 정보만(내 점수 = 10·t − 지금까지 쓴 점수, 내 색, 선/후, 공개 판, 내 베팅과 칸 승패). AI 기억(mem)은 `aiNewMem(씨앗)` 다음, 지난 턴마다 `mem.cur={V,aiPts}`를 넣고 `aiObserve`로 다시 재생. 새 일꾼 `FXWK`(엔진+AI 코드+`rvaiCompute`)에서 그 턴만 계산하고 캐시, 다음 턴은 미리 하나만. 씨앗·캐시 키도 내 입장 정보로만 만듦.
- 1차 89점 → 수정: 씨앗에 상대 베팅이 섞여 있어서 상대 베팅을 바꾸면 결과가 달라졌음(테스트 B7 실패) → 키를 내 입장 정보로만 만들게 바꿈. 숨기기 토글 추가(`bo-rvai`), 화면 읽기 안내 추가, ▲▼는 aria-hidden.
- 최종 96점 근거: 대국 중에는 안 보임(`rvaiAllowed`가 끝난 판일 때만 true. 온라인·AI 대국 중 DOM에 없고 일꾼도 만들지 않는 것을 테스트로 확인). 일꾼 결과 = 같은 계산을 바로 했을 때 결과. 상대 베팅을 바꿔도 결과 같음. 합계 ≤ 내 점수. 26턴 판 마지막 턴 처음 계산 0.1~0.3초(일꾼이라 화면 멈춤 없음).
- 한계: Ultimate가 무작위를 쓰므로 "가능한 한 가지 답". 학습 데이터(AI_LRN)가 기기마다 다르면 값이 조금 달라질 수 있음. 판 전체 보기에서는 점선 칸이 작게 보임.

## 2. 오늘의 퍼즐
- 설계: 한국 날짜로 씨앗 고정(`bo-puzzle|v1|YYYY-MM-DD`) → 모든 폰이 같은 문제, 서버 사용 없음. 요일별 난이도(일·토 어려움, 월·화 쉬움). 유형: 막기(가장 적게 써서 확실히 막기), 이기기(가장 적게 써서 확실히 오목), 세 칸 고르기(4지선다).
- 판정(엄밀): 상대는 가진 점수 안에서 어떤 베팅이든 한다고 보고, 엔진 `settle`+`fiveLines`로 8가지 결과를 모두 따짐. 베팅형 정답 = 확실히 해냄 + 합계가 최소(정답 집합). 고르기형 = 정답 후보가 정확히 하나인지 생성할 때 검사.
- 설명: 자동 문장("상대가 C만 가져도 오목 · 거기에 최대 11점 · 같으면 상대 돌 → C에 12점 이상 → 합계 14점"). 이 규칙이 모든 베팅에서 엔진 판정과 같은지 생성할 때 전수 검사하고, 다르면 그 문제는 버림 → 설명이 늘 정확함.
- 1차 90점 → 수정: 묶음 계산 버그(마스크 7 누락), 난이도 표시를 실제 구조 기준으로, 고르기 설명을 정답 비용과 맞춤(X+1이 아니면 버림), 넓은 화면에서 타일이 규칙 카드 위로 넘침 → 넓은 화면은 두 칸 나란히.
- 최종 95점 근거: 두 폰 같은 문제, 정답·오답 판정, 40일치 자동 검사(정답 예시 통과, 1점 더 쓰면 오답, 1·1·1 오답, 고르기 정답 1개) 0건 오류. 60일 생성 실패 0, 하루 생성 1~70ms. 연속 기록(`bo-pzs`), 다음 날 새 문제.
- 한계: 패턴이 기본형 5가지(넉 줄·석 줄 막기/이기기·이중 넉 줄·고르기)라 몇 주 지나면 비슷하게 느껴질 수 있음. 6목 함정 같은 특수형은 아직 없음. 하루 한 번만 제출.

## 3. 내 플레이 분석(전적 탭)
- 항목: 선/후로 시작한 판의 승률, 승부 칸(그 칸 결과에 따라 이번 턴 승부가 바뀌는 칸) 평균 베팅과 보통 칸 평균, 1점씩만 건 턴 비율, 자주 지는 장면(상대 몰아 걸기 = 마지막 턴 상대 지출이 그 전 평균의 2.5배 이상이고 12점 이상 / 내가 고른 턴 / 상대가 고른 턴 / 시간 초과 / 기권), 랭크전 전적. 이 기기 지난 대국(내가 둔 판) + RK.map.
- 1차 91점 → 수정: 긴 라벨이 잘려서(`상대가 모아서 한 번에 걸 때`) 짧게 바꿈. 5판 미만이면 "참고용" 안내. 판마다 결과를 캐시.
- 최종 96점 근거: 파이썬으로 따로 짠 계산(돌 놓기·오목 판정·승부 칸)과 숫자가 모두 같음(D1). 화면 숫자 확인(D2). 막대는 작게, 문장은 짧게.
- 한계: 기기에 남은 30판 기준. 한 폰 대국(내가 누군지 모름)은 뺌. 랭크 전적은 이번 시즌 것만.

## 5. 대국 중 이모트
- 그림: 보낸 사람의 돌(흑·백)에 얼굴을 그린 캐릭터 12종(안녕·최고·깜짝·메롱·덤벼·아쉽다·힘내·음…·하하·분해·고마워·박수). 인라인 SVG로 직접 그림. 꾸밈은 GS 색(제이드·블루·라임·오렌지). 그림 모음: `shots/emote_gallery.png`(흑·백), 고르기 창 `shots/ph_dark_emopick.png`·`ph_light_emopick.png`, 말풍선 `shots/ph_dark_emobubble.png`·`t_emo_recv.png`.
- 위치: 상단 오른쪽 작은 버튼 → 4×3 고르기 창. 말풍선은 보낸 사람 바 옆(위 = 상대, 아래 = 나)에 2.5초. 누를 수 없음(pointer-events 없음). 움직임 줄이기 설정이면 흐려졌다 사라지기만 함. 화면 읽기: "상대: 깜짝".
- 횟수 제한: 폰에서는 8초에 1번, 1분에 4번(버튼에 남은 시간 고리, aria-label에 "N초 뒤 가능"). 서버 규칙은 6초 간격.
- 전달: 기존 접속 표시 문서 `rt/g-{gid}/p/{uid}`의 `presence.emo={k,t}`(쓰기 1번, 20초 '살아 있음'에 실려도 바뀌지 않으면 검사 통과). 규칙: g- 방에서만, 처음 만들 때 금지, 한 번 넣으면 빼기 금지, 6초 이상 간격, 시각은 서버 기준 10분 전~1분 뒤. `fb-adapter.js` 사본: presence()가 쓰기 결과를 돌려줌 → 거부되면 이전 값으로 되돌림(되돌리지 않으면 20초 '살아 있음'이 계속 실패하는 문제를 막음).
- AI: 아주 드물게 반응. 사람이 보낸 이모트에 답(25%, 랭크전 AI 20%), 대국 끝(AI가 이기면 20%, 지면 30%), 판당 최대 3번, 20초 간격. 공개된 일에만 반응(정보 누출 없음). 랭크전 AI도 같은 방식이라 사람처럼 보이는 것과 어긋나지 않음.
- 상대 이모트 끄기: 고르기 창 스위치 + 설정 "상대 이모트 보기".
- 1차 88점 → 수정: 말풍선 안 그림이 너무 작음(퍼센트 패딩이 화면 폭 기준이었음), 다크에서 흑돌 그림 대비 부족 → 크림색 바탕, 대국 밖(복기 등)에서 AI 말풍선이 뜨던 문제 → 이모트를 쓸 수 있는 대국에서만 표시.
- 최종 95점 근거: 두 폰 왕복, 내 바·상대 바 위치, 쿨다운 표시·비활성, 규칙 거부 3종(6초 안 다시 쓰기·만들 때 넣기·시각 범위 밖), 8초 뒤 두 번째 왕복, 끄면 안 뜸, AI 답(확률 고정해서 확인).
- 한계: 접속 표시 문서를 지웠다 다시 만들면(방 나갔다 들어오기) 간격 검사를 한 번 건너뛸 수 있음(쓰기 3번이 들어서 실익은 적음). 폰 시계가 1분 넘게 빠르면 이모트가 안 보내짐(토스트로 알림, 대국에는 영향 없음).

## 7. 시즌 결산
- 설계: 시즌이 바뀐 뒤 처음 앱을 열면 한 번(`bo-recap`). 랭크전을 둔 사람만. 최종 티어 문양(`emblem()` 호출만), 최종 점수·순위·시즌 전적·최고 연승·가장 많이 만난 상대·다음 시즌 시작 점수(한 단계 아래 티어 최저점, 배치 5판). 공유 버튼: Web Share(파일) 되면 공유, 아니면 PNG 저장(1080×1350, 캔버스로 직접 그림).
- 랭크 개편팀(rank3) 연결 지점(`FEAT-MERGE` 표시): rank3 사본에 `rankCalc(SS,LT,docs,bdocs)`가 있으면 그것을 씀. 다음 시즌 시작 점수는 `RESET`이 있으면 그것, 없으면 같은 값의 `FX_RESET=[900,900,900,1100,1300,1500,1500]`. `cfg/season{n}`(시즌 n 최종 기록 `{n,at,v,p:{자리:[티어,점수,판수]}}`)이 있으면 최종 티어·점수·순위는 그 값으로(모든 폰이 같음). 지금 base에는 없어서, 지난 시즌 마지막 순간으로 시계를 돌려 `rankCompute`를 한 번 계산한 뒤 원래대로 되돌림. 결과 문서를 못 읽게 될 때를 대비해 시즌 중 30초마다 내 기록을 폰에 저장(`bo-rksnap`).
- 1차 90점 → 수정: 전적이 칸을 넘침("29승 16패 1무") → 무승부는 아래 줄로, 긴 글자는 작게. 테스트 날짜 상수 오류 수정.
- 최종 95점 근거: Date.now를 2027-03-02로 바꿔 시즌 경계를 흉내 → 결산 1번 표시, 6승 1패·4연승·많이 만난 상대 3판이 넣은 기록과 같음, 계산 뒤 현재 시즌 상태 그대로, 공유 이미지 생성(0.9MB), 다시 열면 안 뜸, 시즌 1 중에는 안 뜸.
- 한계: 최고 연승·가장 많이 만난 상대는 내가 쓴 결과 기록(res·bres 중 by=나) 기준. 폰에 남은 결과가 3000건을 넘으면 오래된 판이 빠질 수 있음. 관리자 기록이 없으면 순위가 폰마다 조금 다를 수 있음.
